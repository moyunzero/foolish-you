## Implementation Decisions

### Version bump surface

- **D-01:** 营销版本 **`2.4.2`** 同步到 **`app.json` `expo.version` + `package.json` + README / README.zh-CN 徽章**（及文中营销版本表述）。
- **D-02:** iOS `buildNumber` / Android `versionCode` **仓库不改**；交给 EAS production `autoIncrement`（`appVersionSource: local`）。
- **D-03:** 商店叙事以用户确认的实况为准：**线上 `2.4.1` 已完整上架** · **待提交 `2.4.2`**（勿再写「待提交 2.4.1」或「线上仅 2.4.0」）。
- **D-04:** `docs/CONFIGURATION.md` 版本表 / 商店状态行 **一并改到 2.4.2**，与 app.json / package.json / README 对齐。

### What's New copy（SHIP-01）

- **D-05:** 变盘披露为 **单独一条、说清楚**，须点明：**更新后尚未游玩的日期盘面可能变化**；**进行中的进度会保留**。
- **D-06:** 功能向 bullet **三条**（再加变盘条）：① 数独/二进制周节奏难度更清晰；② 数回难度梯度拉宽；③ 数绘图案库扩充到 120。
- **D-07:** **Claude 按历史 What's New 风格起草中/英终稿**，写入 `docs/CONFIGURATION.md`（可执行时微调措辞，但须保留 D-05 语义）。
- **D-08:** bullet 顺序 **功能在前、变盘在后**；原「`2.4.1` · 待提交」块改为 **已上架**；新建「`2.4.2` · 待提交」块。

### Hand QA / Maestro

- **D-09:** 本 phase **必须有 Maestro 证据**（可复现 flow + evidence 目录）才算完成；不可仅有手测文档。
- **D-10:** Maestro **最少**：四种题型 **各一条 smoke 进游戏**。
- **D-11:** **手测清单必写且需签核** — 覆盖 ROADMAP：四题型各至少一天、**周一松 / 周日紧抽样**、**进行中存档重开不丢盘**；Maestro 烟测 **不替代**手测。
- **D-12:** 证据与说明落在新目录 **`docs/qa/v2.4.2-ship/`**；脚本可参考 v2.4 Sunday Special；**本机人工跑** Maestro（不接 CI）。

### Ship gate & sign-off

- **D-13:** phase「完成」= **仓库就绪**（版本 + What's New + CI + 手测/Maestro 证据与文档）；**不含** EAS production / 提审。
- **D-14:** CI 门槛 = AGENTS 四件套：`npm run typecheck && npm test && npm run test:migration && npm run lint`。
- **D-15:** 签核记录在 phase **`VERIFICATION.md` 勾选矩阵 + 人工签字**（同 v2.4 惯例）。
- **D-16:** 本 phase **一并**把 `.planning/REQUIREMENTS.md` 中 NONO-01 软措辞（≈120 / roughly balanced）改成与 CONTEXT 一致的 **exact 120 + hist 17/17/17/17/17/17/18**。

### Claude's Discretion

- What's New 三条功能 bullet 的具体中/英措辞（须符合 D-05..D-08，短、可感、不剧透玩法规则）。
- Maestro flow 文件命名、是否复用/改编现有 `.maestro/flows/` smoke、Dev 假日期强制题型的具体步骤（须满足 D-10）。
- `docs/TESTING.md` 新增 v2.4.2 小节的写法与指向 `docs/qa/v2.4.2-ship/` 的链接结构。
- VERIFICATION 矩阵行拆分粒度（CI / What's New / Maestro / 手测抽样各项）。
