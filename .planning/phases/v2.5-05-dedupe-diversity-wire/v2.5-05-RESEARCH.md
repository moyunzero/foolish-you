## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Hash ring (DIV-01)
- **D-01:** Capacity **200 hashes per `gameType`** (four independent rings).
- **D-02:** Append on **complete only** — abandon / incomplete do not consume ring slots.
- **D-03:** Eviction is **FIFO** (drop oldest when over capacity).
- **D-04:** Avoid set used at generate/select time is the ring for the **selected** `gameType` (plus any existing single `previous.puzzleHash` behavior may be subsumed or kept as subset — RESEARCH discretion, prefer one avoid set API).

#### Diversity retries (DIV-02)
- **D-05:** Within target tier, retry generation/selection with varied sub-seeds up to **~40** attempts while `puzzleHash ∈ avoid`.
- **D-06:** If retries exhaust: **relax avoid** and accept a puzzle even if hash was recent — prefer “have today’s game” over absolute uniqueness. Do **not** throw or fall back to builtin as the primary exhaustion path.
- **D-07:** Soften-toward-easier remains the forTier internal policy when the **tier pool** is empty; avoid-exhaustion (D-06) is separate from tier-soften.

#### Selector / hydrate wire (TIER-01 wiring)
- **D-08:** On **first create** for `dateKey`: load mastery → `resolveTargetTier({ gameType, mastery, dateKey, nowMs })` → `generate*ForTier(seed, targetTier)` (with avoid retries). Do **not** leave hydrate on legacy weekday-only generate for the adaptive path.
- **D-09:** Weekday difficulty participates **only** via `resolveTargetTier`’s ±1 nudge. Adaptive forTier calls must **not** also apply `dateKey` weekday bucket guides (no double nudge). Legacy `generate*(seed, dateKey?)` may remain for tests/compat but must not be the hydrate create path after this phase.
- **D-10:** MAST-04 unchanged: once snapshot written for `dateKey`, later mastery/hash updates must not rewrite today’s puzzle.
- **D-11:** Type pick stays equal-weight / existing `APP_SALT` rules — mastery never forces `gameType`.

#### Persistence
- **D-12:** Played-hash ring lives in a **separate storage module + key** (e.g. `playedHashStorage`), with validation/migration — not merged into the mastery blob.
- **D-13:** On complete: persist mastery update and hash-ring append in the **same complete flow**, sequentially. Either write may fail independently with `console.warn` (or existing logging); do not roll back the other or the completion UX.
- **D-14:** Empty/missing ring migrates to empty per-type lists; never wipe mastery on hash migration failure.

#### Carried forward (do not reopen)
- MAST-01..04, TIER-02..05 forTier APIs already shipped
- No UI difficulty badges
- Offline-first; storage safety via `lib/storage/` patterns

## Summary

本阶段把已落地的 **mastery + `resolveTargetTier` + 四个 `generate*ForTier`** 接到 **hydrate 首次建局** 路径，并新增 **按 `gameType` 的 played-hash 环（容量 200、仅 complete 追加、FIFO）**，在目标档内用确定性 sub-seed 重试约 40 次避开近期 hash；耗尽后 **放宽 avoid 仍返回一局**（不抛错、不以 builtin 作为 avoid 主路径）。

现状缺口（已核实）：

- `buildNewDailySnapshot` → `selectDailyGameSafe` → `selectDailyGame` 仍调用 **legacy** `generate*(seed, dateKey)`（weekday 给定数/band 在 generator 内），**未**读 mastery / forTier。[VERIFIED: codebase `lib/daily/dailyHydrate.ts`, `lib/puzzles/dailySelector.ts`]
- Avoid 仅为单个 `previous.puzzleHash`，循环上限 **50**（非 ring）。[VERIFIED: codebase]
- `persistStatus('completed'|'abandoned')` 已写 mastery；**无** hash ring 追加；abandon 也不应追加（D-02）。[VERIFIED: codebase `contexts/DailyGameContext.tsx`]
- 四个 `generate*ForTier(seed, targetTier)` **不接受** `avoidHashes`；内含各自 soften / attempt 预算。[VERIFIED: codebase]

**Primary recommendation:** 新增 `lib/storage/playedHashStorage.ts`（镜像 `masteryStorage`）；在 `buildNewDailySnapshot` 并行 `loadMasteryState` + `loadPlayedHashes`；扩展 `selectDailyGame` 在 type-pick 后 `resolveTargetTier` → 外层 avoid 重试包装 `generate*ForTier`；complete 路径在 mastery 之后 `appendPlayedHash`；`selectDailyGameSafe` 继续薄包装同一 `selectDailyGame`。

## Architecture Patterns

### System Architecture Diagram

```
hydrateDailyGame(today)
  │
  ├─ loadDailySnapshot → dateKey===today? → prepareTodaySnapshot (FREEZE) → return
  │
  └─ buildNewDailySnapshot
        │
        ├─ Promise.all([ loadMasteryState(), loadPlayedHashes() ])
        │
        └─ selectDailyGameSafe({ dateKey, previous, forceGameType, mastery, avoidByType })
              │
              └─ selectDailyGame
                    ├─ pickGameType (APP_SALT / equal weight) ── unchanged
                    ├─ targetTier = resolveTargetTier({ gameType, mastery, dateKey, nowMs })
                    ├─ avoid = Set(ring[gameType] ∪ optional previous.puzzleHash)
                    ├─ for attempt in 0..AVOID_MAX-1:
                    │     seed' = deriveSubSeed(seed, `daily-avoid-${gameType}-${attempt}`)
                    │     puzzle = generate*ForTier(seed', targetTier)   // may internal-soften
                    │     if puzzle.puzzleHash ∉ avoid → return
                    └─ relax: generate*ForTier(deriveSubSeed(seed,'daily-avoid-relax'), targetTier)
                              // accept even if ∈ avoid; do NOT builtin here

complete (persistStatus 'completed')
  ├─ persistSnapshot (status completed)
  ├─ recordCompletion / streak / rating
  ├─ saveMasteryState(applyMasteryOutcome(...))   // existing
  └─ appendPlayedHash(gameType, puzzleHash)       // NEW; sequential; warn on fail

abandon
  └─ mastery update only — NO hash append (D-02)
```

### Pattern 1: Storage module mirror (`masteryStorage`)

**What:** 独立 AsyncStorage key + `version` + normalize on read；缺失/损坏 → 安全默认；`version > app` → warn + 空环。  
**When to use:** 所有新持久化 blob（D-12）。  
**Schema（推荐 discretion）:**

```typescript
// Source: research recommendation mirroring masteryStorage / completionHistory slice
// constants/config.ts
export const PLAYED_HASH_STORAGE_KEY = '@foolish-you/played-hash-v1';
export const PLAYED_HASH_STORAGE_VERSION = 1;
export const PLAYED_HASH_RING_CAPACITY = 200; // D-01
export const AVOID_HASH_MAX_ATTEMPTS = 40;    // D-05

// Persisted shape
type PersistedPlayedHashes = {
  version: number;
  byType: Record<GameType, string[]>; // FIFO oldest → newest; max 200 each
};
```

`appendPlayedHash(gameType, hash)`：读 → 若末尾已是同 hash 可 no-op（可选）→ push → `slice(-CAPACITY)` → save。  
**勿** bump `STORAGE_VERSION` / `MASTERY_STORAGE_VERSION` 仅因本环。[CITED: docs/CONFIGURATION.md § Storage version bumps]

### Pattern 2: One avoid set API (D-04 discretion)

**What:** Select 时构造 `ReadonlySet<string>`：`ring[gameType]` ∪（若存在）`previous.puzzleHash`。  
**When to use:** 所有 build* 路径；废弃单独的 `avoidHash?: string` 分支。  
**Why Set:** 成员检测 O(1)；存储仍用有序 `string[]` 保 FIFO。  
**Subsume previous:** 始终把 `previous.puzzleHash` 并入 avoid（即使跨类型，误伤为零）——保留现有「避开昨日题面」语义且统一 API。[VERIFIED: codebase 当前把 previous.puzzleHash 传给所选类型 builder]

### Pattern 3: Outer avoid loop + forTier（不改 forTier 签名）

**What:** `generate*ForTier` 保持 `(seed, targetTier[, options])`；avoid 在 `dailySelector` 外层。  
**When to use:** 四类型统一；Nonogram 也靠换外层 seed 换 pattern/transform。  
**Sub-seed（discretion 推荐）:**

```typescript
// Source: existing dailySelector avoid + rng.ts pattern [VERIFIED: codebase]
const attemptSeed = deriveSubSeed(seed, `daily-avoid-${gameType}-${attempt}`);
const result = generateSudokuPuzzleForTier(attemptSeed, targetTier);
if (!avoid.has(result.puzzle.puzzleHash)) {
  return { puzzle: result.puzzle, puzzleHash: result.puzzle.puzzleHash };
}
// after AVOID_HASH_MAX_ATTEMPTS:
const relaxed = generateSudokuPuzzleForTier(
  deriveSubSeed(seed, `daily-avoid-${gameType}-relax`),
  targetTier,
);
return { puzzle: relaxed.puzzle, puzzleHash: relaxed.puzzle.puzzleHash };
```

内层 forTier 仍可 soften（D-07）；与 avoid-relax **正交**：先尽量 exact/softened-forTier 且 hash∉avoid；再接受 ∈avoid 的 forTier 结果。

### Anti-Patterns to Avoid

- **Double weekday nudge:** hydrate 仍调 `generateSudokuPuzzle(seed, dateKey)`（内含 `sudokuGivensForDate`）同时又 `resolveTargetTier` — 禁止。forTier **不传** `dateKey`。[VERIFIED: `lib/puzzles/sudoku/generator.ts` 仍有 weekday givens]
- **Avoid-exhaust → builtin:** 现有 SL builder 耗尽走 `getSlitherlinkBuiltinPuzzle()`；adaptive 路径禁止以此作为 D-06 主路径（safe 的 solvability 灾备另论）。
- **把 ring 写入 mastery / daily snapshot:** 违反 D-12 与 storage bump 纪律。
- **abandon 追加 hash:** 违反 D-02。
- **在 forTier 内再套 40×avoid 且改四文件合约:** 过度；外层包装足够。
- **改 type-pick / APP_SALT:** 违反 D-11 / AGENTS。

## Common Pitfalls

### Pitfall 1: Nonogram Expert 池薄 + avoid 耗尽

**What goes wrong:** Expert `difficultyTier` hist ~17；外层 40 次仍可能全撞 ring（尤其老用户 ring 近满）。  
**Why:** 库过滤非 carve；唯一性靠 pattern×transform。[VERIFIED: STATE.md freeze audit + `generateNonogramPuzzleForTier`]  
**How to avoid:** 严格实现 D-06 relax；测「avoid 覆盖该 seed 下全部可产出 hash 时仍返回 puzzle」。  
**Warning signs:** hydrate 抛错 / 卡住；或误回 builtin。

### Pitfall 2: 双重 weekday nudge

**What goes wrong:** 难度被 ±1（resolve）再叠加 weekday givens/band。  
**Why:** legacy generator 仍接受 `dateKey`。  
**How to avoid:** hydrate/adaptive 路径只调 forTier；单测断言 builders 不再调用 `generateSudokuPuzzle(..., dateKey)`（可 spy 或固定 mastery 对比）。  
**Warning signs:** 同 mastery 下周一/周五 forTier guide 仍随 weekday 变（不应）。

### Pitfall 3: Freeze 回归被破坏

**What goes wrong:** rehydrate 因 mastery/ring 变化重跑 select。  
**Why:** 误改 `hydrateDailyGame` 的 `dateKey === today` 短路径。  
**How to avoid:** 保留短路径；扩展 `__tests__/lib/mastery/freezeMastery.test.ts`（完成一局写 ring 后同日 rehydrate hash 不变）。  
**Warning signs:** freeze 测红。

### Pitfall 4: 外层×内层 attempt 乘积（CPU）

**What goes wrong:** Sudoku/Binary/SL：40 avoid ×（40 attempts × ≤4 softens）最坏很重。  
**Why:** forTier 未感知外层 avoid。  
**How to avoid:** 接受 D-05 锁定；勿在本阶段再加大外层；必要时后续优化 forTier 接受 optional avoid（**非本阶段范围**）。hydrate 已在 `runAfterInteractions` 中。[VERIFIED: `dailyHydrate.ts`]  
**Warning signs:** 低端机首次建局明显卡顿。

### Pitfall 5: Gallery / 无 mastery 调用方

**What goes wrong:** `resolveGalleryCell` 调 `selectDailyGameSafe({ dateKey })`；接线后走 forTier+默认 mastery，图鉴格与旧 weekday 盘可能不一致。  
**Why:** 单路径强制 forTier。  
**How to avoid:** 缺省 `DEFAULT_MASTERY` + 空 avoid（确定性按 dateKey）；变盘归 SHIP-01（v2.5-06）。不要为 gallery 分叉第二套生成器。  
**Warning signs:** gallery 单测 hash 金样失败 — 更新金样或锁默认 mastery。

### Pitfall 6: Safe fallback 与 avoid-relax 混淆

**What goes wrong:** avoid 耗尽时掉进 `getFallbackDailySelection` / SL builtin。  
**Why:** 旧 SL builder 模式惯性。  
**How to avoid:** avoid-relax 必须仍 `generate*ForTier`；`dailySelectorSafe` 仅在 **不可解** 时 fallback（灾备）。  
**Warning signs:** 测到 fallback hash / builtin id。

```typescript
// Source: pattern from completionHistoryStorage.slice(-MAX) [VERIFIED: codebase]
export async function appendPlayedHash(
  gameType: GameType,
  puzzleHash: string,
): Promise<boolean> {
  const state = await loadPlayedHashes();
  const prev = state.byType[gameType];
  const next = [...prev, puzzleHash].slice(-PLAYED_HASH_RING_CAPACITY);
  return savePlayedHashes({
    byType: { ...state.byType, [gameType]: next },
  });
}
```
